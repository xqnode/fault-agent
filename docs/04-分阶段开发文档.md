# DOC-04 分阶段开发文档

> 文档编号：DOC-04  
> 文件：`04-分阶段开发文档.md`  
> 项目：制造业智能故障分析 Agent  
> 原则：先业务，后 AI；不跳跃；每阶段有验收标准  
> 依据：DOC-01  
> 配套：DOC-02 数据库、DOC-03 API

---

## 0. 总原则

1. **严格按 Phase 1 → 8 顺序开发**，未验收通过不进入下一阶段。
2. **先完成可运行的工业运维闭环，再接入 Agent。**
3. MVP 必做工程约束不可省：状态机、报警快照、证据上限、RAG metadata filter、分析幂等、结单回写。
4. 不做：复杂 RBAC、多租户、真实 PLC/MES、Multi-Agent、MCP、复杂 ML 预测。
5. 每次只交付一个可验证小切片；代码保持简单可运行。

技术基线：

```text
后端：Python 3.11+ / FastAPI / SQLAlchemy 2.0 / PostgreSQL
向量：pgvector（本地可用 Chroma 临时替代，但主路径按 pgvector）
前端：Vue3 / Vite / Element Plus / ECharts
部署：Docker Compose
```

## 阶段总览

| Phase | 名称 | 核心产出 | 是否含 AI | 主要对照 |
|------|------|----------|-----------|----------|
| 1 | 基础业务系统 | 表结构 + CRUD + 状态机/结单 | 否 | DOC-02 / DOC-03 |
| 2 | 设备数据模拟 | Simulator + 剧本 + 自动报警 | 否 | DOC-03 模拟器 |
| 3 | Dashboard | 监控大屏与趋势 | 否 | DOC-03 Dashboard |
| 4 | RAG | 文档入库 + 过滤检索 | 检索能力 | DOC-02 知识表 |
| 5 | Agent Tools | 5 个独立 Tool | Tool 层 | DOC-01 Agent Tools |
| 6 | LangGraph Agent | 证据分析主流程 | 是 | DOC-01 / DOC-03 分析 |
| 7 | 可视化 + HITL | SSE 轨迹 + 确认建单 | 是 | DOC-03 analysis/decision |
| 8 | 部署 | Compose 一键演示 | - | 全文 |

建议黄金演示路径（最终验收）：

```text
inject SMT_TEMP_RISE_001
→ 报警
→ AI 分析（可 MOCK_LLM）
→ 工程师确认
→ 创建工单
→ 结单回写
```

## Phase 4：RAG

### 目标

具备按设备类型过滤的知识检索能力，暂不接 Agent。

### 任务清单

- [ ] 建 `knowledge_document` / `knowledge_chunk`
- [ ] 启用 pgvector（或临时 Chroma，但接口语义对齐）
- [ ] 文档切块 + embedding
- [ ] metadata 必含：`device_type` / `doc_type` / `alarm_types` / `source_doc`
- [ ] 检索默认按 `device_type` 过滤
- [ ] 准备 SMT 高温 SOP 等演示语料
- [ ] 提供 ingest / search 调试接口或脚本

### 明确不做

- Agent 编排
- Hybrid Search / Rerank / Query Rewrite

### 验收标准

```text
✓ SMT 查询在有区分语料时不会返回 ROBOT/REFLOW 专属文档
✓ 检索结果可追溯到 source_doc / chunk
```

### 完成标志

> RAG 是“给 Agent 用的知识工具”，不是独立聊天机器人。

## Phase 5：Agent Tools

### 目标

把数据访问封装成可单测的 Tool，禁止 LLM 直连 SQL。

### 任务清单

实现并单测：

| Tool | 要求 |
|------|------|
| `get_device_info` | 返回设备基础信息 |
| `get_sensor_data` | 聚合 + 多信号关联摘要，不返回海量原始点 |
| `get_fault_history` | 同设备/同类型相似故障 |
| `get_work_order_history` | 历史维修方案与结果 |
| `search_knowledge_base` | 必须带 device_type metadata filter |

分层：

```text
Tool → Service → Repository / DB
```

### 验收标准

```text
✓ 每个 Tool 有独立测试（正常 / 空结果 / 异常入参）
✓ get_sensor_data 输出为聚合摘要
✓ search_knowledge_base 默认过滤机型
```

### 完成标志

> Tool 层稳定后，再接 LangGraph。

## Phase 6：LangGraph Agent ⭐

### 目标

完成证据驱动的故障分析主链路。

### 任务清单

- [ ] `FaultAnalysisState`（含 `evidence_round` / `max_evidence_rounds=2~3`）
- [ ] 节点：
  - Load Alarm
  - Plan Analysis（合并原 Analyze+Plan）
  - Collect Evidence
  - Evidence Check（有上限）
  - Root Cause Analysis
  - Generate Report
- [ ] 条件边：证据不足且未达上限 → 继续收集；否则出报告
- [ ] 结构化 JSON 报告（禁止只返回大段 Markdown）
- [ ] 分析幂等与 `alarm`/`analysis` 状态联动
- [ ] 支持 `MOCK_LLM=1` 确定性输出

### 验收标准

```text
✓ 黄金报警可生成结构化报告
✓ 原因均引用 Evidence
✓ 达 max_evidence_rounds 不死循环
✓ 重复 POST 同一 alarm 不产生并行 RUNNING
✓ MOCK_LLM=1 可离线跑通
```

### 完成标志

> 项目最核心能力可用。
